### 行为契约（已由单测覆盖）

- `App.test.ts` "search flow sequence" #1：OPEN_MODAL 'search' → SET_SEARCH 'login' → CLOSE_MODAL
  → `state.searchQuery === 'login'`，`state.modal === 'none'`。
- `App.test.ts` "search flow sequence" #2：已有一个 query 'work'，再次 `/` 进 SearchModal → Esc 取消
  → `searchQuery` 保持 'work' 不变（**取消 ≠ 清空**）。
- `App.test.ts` "search flow sequence" #3：help 模态被 search 模态顶替
  → `state.modal === 'search'`，`state.modalContext === {}`。
- `SessionPane.test.ts` `filterSessions` 10 例：displayName / cwd / id 三类匹配、
  大小写不敏感、空 query 保留原引用、空 sessions 全空、无命中空数组、多字段命中不重复。
- `keyActionRouter.test.ts` "/" opens search modal：单字符 `/` 触发 OPEN_MODAL 'search'。
- `useEscapeToCancel.test.ts` 3 例：仅 `key.escape === true` 触发 onCancel；
  普通字符 / `escape` 字面量 / Tab / Enter 均不触发。

## 步骤

- [ ] **Step 1：构建**

  ```bash
  npm run build
  ```

  期望：命令成功，`dist/cli.js` 存在。

- [ ] **Step 2：启动 ccsm，确认完整 session 列表**

  ```bash
  ./dist/cli.js
  ```

  期望：两栏 UI 渲染，project 列表非空，**Sessions pane 显示完整 session 列表**（顶部计数为总数，例如 `Sessions (12)`）。

- [ ] **Step 3：按 `/`，观察 SearchModal 弹出**

  在主视图（默认焦点 Projects pane 也可，焦点不影响 `/`）按 `/`。

  期望：
  - 弹出黄色边框的 **Search sessions** 模态，顶部有可编辑的输入框。
  - 模态底部副标题：`Enter to apply · Esc to cancel`。
  - 如果之前已用过搜索，输入框**预填**上次的 query（`initial={state.searchQuery}`）。
  - 模态外的 session 列表**不变**（过滤要 Enter 才生效；这是契约）。

- [ ] **Step 4：输入关键字 + Enter，验证列表过滤**

  在 SearchModal 内输入关键字（例如 `login`），按 Enter。

  期望：
  - 模态关闭，回到主视图。
  - Sessions pane 顶部计数变为 **`x/y`** 形式，例如 `Sessions (2/12)`，表示过滤后 x 个、原始 y 个。
  - 仅显示 `displayName` 含关键字、或 `cwd` 含关键字、或 `id` 以关键字开头的 session。
  - 匹配大小写不敏感：`LOGIN` / `Login` / `login` 等价。
  - 如果 0 个匹配，显示 `No sessions match "login"` 暗色提示。

- [ ] **Step 5：边界 case 验证（覆盖 filterSessions 三类匹配 + 边界）**

  - **displayName 命中**：用 `bug` / `fix` / `database` 等常见单词验证包含匹配。
  - **cwd 命中**：用 `personal` / `db` / `work` 验证 cwd 路径子串匹配；path 含 `/` 自动 escape，不需要额外转义。
  - **id 前缀匹配**：用 `sess-login` 之类前缀验证（`filterSessions` 中 `id.startsWith` 是唯一 id 匹配形式）。
  - **大小写**：`LOGIN` 应与 `login` 等价。
  - **多字段命中去重**：构造一个 session 让 `displayName` 和 `id` 都命中关键字，确认列表不重复。
  - **无命中**：用 `zzzzzz` 之类不存在的串确认空态文案。

- [ ] **Step 6：再次 `/` + 修改 query，确认 query 被更新**

  按 `/`，输入新关键字（例如 `work`）覆盖预填的旧 query，按 Enter。

  期望：`state.searchQuery` 变为新值；Sessions pane 头部计数相应变化。
  旧 query 不残留。

- [ ] **Step 7：再次 `/` + Esc 取消，确认 query 不变（**取消 ≠ 清空**）**

  按 `/`，输入新关键字，**不按 Enter，按 Esc**。

  期望：
  - SearchModal 关闭。
  - **session 列表保持 Esc 之前的过滤状态**（即上一步 Enter 的 query 仍然生效）。
  - 这是契约：`useEscapeToCancel` 仅触发 `CLOSE_MODAL`，不派发 `SET_SEARCH`。

- [ ] **Step 8：当前过滤状态保持（query 未清空）**

  期望：Sessions pane 头部仍显示 `Sessions (x/y)` 形式的计数，列表仍是
  Step 6 / 7 之后的状态。

- [ ] **Step 9：主视图按 Escape 清除过滤（⚠️ 已知 limitation，详见下方）**

  当前已应用的过滤下，**在主视图按 Escape**。

  期望（按 brief Step 2）：
  - `state.searchQuery` 被清空为 `''`。
  - Sessions pane 头部恢复为 `Sessions (y)` 形式（无 `x/y`）。
  - 完整 session 列表恢复。

  ⚠️ **当前代码未实装此行为**（详见下方「Step 2 已知 limitation」）。
  本清单执行结果预期为 **list 不变**，需后续 task 补：
  - `src/tui/keyActionRouter.ts` 在 main view（modal === 'none'）分支
    增加 `if (key.escape && state.searchQuery) { dispatch SET_SEARCH ''; return; }`
  - 或将 `useKeybindings.onClearSearch` 从 no-op 改为派发 `SET_SEARCH ''`。
  - 建议**仅在 query 非空时**清空，避免 Esc 在 query 已空时被滥用为额外语义。

- [ ] **Step 10：回归确认**

  - 反复 `/` + 输入 + Enter + Esc，UI 不卡死、不崩溃。
  - 过滤生效后，状态栏、project 列表、其它键（`r`/`d`/`c`/`n`/`,`/`?`）
    不受 searchQuery 影响（设计契约：searchQuery 只作用于 SessionPane 过滤）。
  - 退出 ccsm（`q`）后重启，新 session 仍按预期扫描和显示（query 不持久化，
    这是 design 选择：search 是临时 UI 状态，不写入 state.json）。

- [ ] **Step 11：如发现问题**

  - **`/` 不弹模态**：检查 `src/tui/keyActionRouter.ts` L126-127
    `input === '/'` 分支存在并 dispatch OPEN_MODAL 'search'。
  - **Enter 不提交**：检查 `src/tui/modals/SearchModal.tsx` L21
    `TextInput onSubmit` 是否调到 `onSubmit(q)`；App 端 L307-310 是否
    `dispatch SET_SEARCH q + CLOSE_MODAL`。
  - **过滤不生效**：检查 `src/tui/panes/SessionPane.tsx` L55
    `filterSessions(sessions, searchQuery)`；`filterSessions` 逻辑 L30-39。
  - **Esc 在主视图意外关进程**：当前 main view 分支不处理 Esc；
    如有人改后让 Esc 退出，需要回退（设计契约：quit 走 `q` / Ctrl+C，
    见 Task 9.9）。
  - **Esc 在 SearchModal 把 query 也清了**：当前不会发生；
    如要改成"取消即清空"应明确契约并补回归测试
    （`App.test.ts` "search flow sequence" #2 当前断言 `searchQuery` 保持不变，
    改动需同步更新该用例）。

## Step 2 已知 limitation（重要）

**主视图 Escape 清除过滤功能在当前代码中未实装**：

- `src/tui/App.tsx` L188-204 的 `useKeybindings(...)` 调用把
  `onClearSearch` 传为 `() => {}` no-op。
- `src/tui/keyActionRouter.ts` 在 main view 分支（L86 之后）不处理
  `key.escape`，仅在 `state.modal === 'confirm'` 分支（L77）吞掉 Esc。
- `src/tui/hooks/useKeybindings.ts` L48 把 Esc 路由到 `cbs.onClearSearch()`，
  但 App 端该回调是 no-op。

**结论**：按 brief Step 2「在主视图按 Esc 清除过滤」当前**不会发生**。
