# Task 9.4 — `n` 新建 session 手动验证清单

> 手动验证清单：在**真实 macOS Terminal.app**（真实 GUI）中启动 `ccsm`，
> 在 **project 上**按 `n`，确认 Terminal.app 弹出新窗口，且工作目录
> / 命令正确：
>
> ```
> cd '<project.cwd>' && claude
> ```
>
> 本清单需要真实 GUI（Terminal.app 焦点切换 + 新窗口弹窗），无法在沙箱
> / CI 中自动执行。请在本地 macOS 终端按步骤执行并勾选。
>
> 沙箱侧验证（dispatch 参数与 escape 单元）见同目录
> `tests/actions/newSession.test.ts` 与 `tests/terminal/escape.test.ts`
> （已在本任务一并跑通，详见 `.superpowers/sdd/task-9.4-report.md`）。

## 前置条件

- macOS（Terminal.app / iTerm2 / Warp 任一已装）
- Node.js >= 18，`npm install` 完成
- 已 `npm run build`，`dist/cli.js` 存在
- `~/.claude/projects/` 至少有一个项目目录（用于在 project pane 上聚焦）

## 代码路径速查（确认预期）

- `n` 按键路由：`src/tui/keyActionRouter.ts` L116-122
  → `focusedPane === 'projects'`（默认）时，按 `n` 取出
  `state.projects.find(p => p.key === state.selectedProjectKey)`，若存在
  则回调 `opts.onNewSession(proj)`；未选中 project 时 no-op（不会跨 pane
  误触发）。
- 新建 session 副作用：`src/tui/App.tsx` L243-250
  → `void newSession(project, state.terminal).catch(...)`，terminal
  取自当前 state（按 settings 切换而重建 callback）。
- 派发逻辑：`src/actions/newSession.ts` L36-44
  → `dispatchOpen(terminal, { cwd: project.cwd, command: 'claude' })`
  → **不预转义** cwd / command，也不附加 `--resume` / `--continue` /
    任何其它 flag（设计契约：newSession = 全新 session）。
- Terminal.app 后端：`src/terminal/terminal-app.ts` → `buildTerminalAppScript`
  → AppleScript `do script "cd '<cwd>' && <command>"`：
  - cwd 用 `escapeForAppleScript`（POSIX 单引号转义，仅 `'` → `'\''`）
  - command 用 `escapeForAppleScriptDoubleQuotes`（先 `\` → `\\` 再 `"` → `\"`）

预期 Terminal.app 弹窗命令：

```
cd '<project.cwd>' && claude
```

## 步骤

- [ ] **Step 1：构建**

  ```bash
  npm run build
  ```

  期望：命令成功，`dist/cli.js` 存在。

- [ ] **Step 2：启动 ccsm**

  ```bash
  ./dist/cli.js
  ```

  期望：两栏 UI 渲染，project 列表非空，状态栏 OK；焦点默认在
  **Projects pane**（不是 Sessions pane）。

- [ ] **Step 3：选中任一 project（不要切到 session pane）**

  用 ↑/↓ 在 Projects pane 中选中一个 project，**不要按 Tab**。
  状态栏底部会显示当前选中 project 的 cwd。

- [ ] **Step 4：按 `n`**

  期望：
  - Terminal.app **跳到前台**（`tell application "Terminal" to activate`）。
  - 弹出**新窗口/标签**，提示符为 `cd '<project.cwd>' && claude`。
  - 命令实际执行：终端显示 Claude Code 启动信息（`claude` 后无
    `--resume` / `--continue` 之类 flag）。
  - `<project.cwd>` 与 UI 状态栏上看到的一致；路径中即使包含空格 /
    引号也应原样执行（单引号上下文内 `&` `|` `;` `$` 全部 inert）。

- [ ] **Step 5：边界样本（建议手测一两个）**

  - **含空格 cwd**：选一个 `~/Library/Mobile Documents/...` 之类含空格的
    project，确认 `cd` 不被截断、Claude Code 在正确目录启动。
  - **含单引号 cwd**（少见）：若本机存在，选中后 Terminal.app 弹窗的 cd
    应正确把 `'\''` 序列拼回原 cwd；若失败则为 escape bug。
  - **manual project**：在 `,` settings 中手动添加的 project（含
    `manual: true`）按 `n` 同样应弹窗到该 path。

- [ ] **Step 6：no-project no-op 回归**

  - [ ] 启动 ccsm 后**立刻按 `n`**（焦点在 Projects pane 但可能没有
    "选中"——取决于 `selectedProjectKey` 初值）。期望：若 state 中已有
    `selectedProjectKey`，Terminal.app 仍会弹窗到该 project.cwd；若未选
    中，no-op，不弹窗也不报错。
  - [ ] 切到 Sessions pane（Tab），按 `n`。期望：**no-op**（不弹窗），
    因为 `n` 只在 project pane 上有意义；这是 design doc §3.3 的契约。

- [ ] **Step 7：回归确认（务必做一次）**

  - `n` 后回到 ccsm UI，不应出现崩溃 / 卡死。
  - 连续多次 `n`（不同 project）仍能正常弹窗。
  - 状态栏底部若显示错误信息（如 "Terminal not authorized"），按 macOS
    `系统设置 → 隐私与安全性 → 自动化` 给 Terminal.app 授权后重试。

- [ ] **Step 8：如发现问题**

  - cwd 截断 / 转义错误 → 提交修复：

    ```bash
    git commit -m "fix(terminal): correct cwd escape in new session"
    ```

  - 命令错误（如意外带上 `--resume`）→ 检视 `src/actions/newSession.ts`
    L36-44，确认 `command` 是字面量 `'claude'`（**不是** `'claude --resume ' + ...`）。
  - project pane 上 `n` 不弹窗 → 检视 `src/tui/keyActionRouter.ts` L116-122
    确认 `n` 路由的是 `onNewSession`（不是 settings / confirm 模态）。
  - 完全不弹窗 → 检视 `state.terminal` 与 `src/terminal/<backend>.ts`
    的对应后端实现。

- **中**：本任务主要靠 GUI 弹窗确认 cwd 与命令，沙箱无 GUI；dispatch
  逻辑、转义、单测都已通过，但 **Terminal.app 真实弹窗的最终视觉确认
  仍需用户在本地手动完成**。清单 Step 4-7 是真正的把关步骤。

  斜杠 / 双引号 / `&` `|` `;` `$` 等元字符，回归风险小。
- **低**：`n` 在 sessions pane 上应 no-op（design doc §3.3 契约）；Step 6
  是这条契约的回归把手。
