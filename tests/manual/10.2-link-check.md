# Task 10.2 — `npm link` 全局验证清单

> 手动验证清单：在仓库根目录执行 `npm link`，确认 `ccsm` 被注册到全局 `PATH` 并能解析到本仓库的 `dist/cli.js`；同时验证从"新 shell 调用 `ccsm`"能走到 Ink boot。

## 前置条件

- macOS（本任务依赖 homebrew 全局 bin 路径 `/opt/homebrew/bin`）
- Node.js >= 18（已验证 v26.0.0）
- 已 `npm install`
- 已 `npm run build`，`dist/cli.js` 存在并有 `+x` + shebang `#!/usr/bin/env node`（Task 10.1 已验证）
- `package.json` 内 `"bin": { "ccsm": "dist/cli.js" }`（已存在）

## 沙箱 / 非 TTY 环境可重复执行

以下脚本可在任何 shell 重现完整检查：

```bash
set -e
cd "$(dirname "$0")/../.."

npm link

CCSM="$(which ccsm)"
test -n "$CCSM" || { echo "FAIL: ccsm not in PATH"; exit 1; }
test "$(readlink -f "$CCSM")" = "/Users/carlos/workspace/cc-manager/dist/cli.js" \
  || { echo "FAIL: ccsm resolves elsewhere"; exit 1; }
head -1 "$CCSM" | grep -q '^#!/usr/bin/env node' \
  || { echo "FAIL: shebang missing"; exit 1; }

"$CCSM" </dev/null
echo "SMOKE LINK OK"
```

## 风险信号

无 CRITICAL。观察一项：

- **OBS-1：PATH 路径差异**：当前 macOS Apple Silicon 上默认 npm prefix 是 `/opt/homebrew`，因此 `which ccsm` 实际落到 `/opt/homebrew/bin/ccsm`（而非部分旧文档默认的 `/usr/local/bin/ccsm`）。若用户在 Intel Mac 或自定义 prefix，`npm link` 会自动落到其 prefix，但 `which` 输出的具体路径会变化。本清单的预期断言改用 `readlink -f` 回溯到本地 `dist/cli.js` 来兼容任何 prefix。
