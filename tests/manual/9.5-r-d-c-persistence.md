# Task 9.5 — `r` / `d` / `c` 跨重启保留手动验证清单

> 手动验证清单：在**真实 macOS Terminal.app**（真实 GUI）中启动 `ccsm`，
> 分别按 `r` / `d` / `c`，然后**重启 ccsm**（保留 `state.json`），确认：
>
> - `r` 改的别名（session / project）重启后仍生效；
> - `d` 删除的手动项目重启后**不再出现**；
> - `c` 复制到剪贴板的 UUID 与 `state.json` 里 `selectedSessionId` 一致。
>
> 沙箱侧验证（action 单测 + state 持久化单元）已在本任务一并跑通，
> 详见 `.superpowers/sdd/task-9.5-report.md`。

## 前置条件

- macOS（Terminal.app / iTerm2 / Warp 任一已装，`pbcopy` 系统自带）
- Node.js >= 18，`npm install` 完成
- 已 `npm run build`，`dist/cli.js` 存在
- `~/.claude/projects/` 至少有一个项目目录
- 至少有一个**手动添加**的 project（用 `,` → settings 添加，或事先
  手工编辑 `~/.config/cc-manager/state.json`），否则 `d` 没目标

## 代码路径速查（确认预期）

- `r` 路由：`src/tui/keyActionRouter.ts` L114-115
  → `dispatch({ type: 'OPEN_MODAL', modal: 'rename' })`，模态由
  `RenameModal` 收集新名后通过 `useKeybindings` 的 `onRename`
  回调路径调用 `renameSession` / `renameProject`。
- `r` 写盘：`src/actions/renameSession.ts` L25-30 /
  `src/actions/renameProject.ts` L26-31
  → 都走 `setAlias(type, key, value)`，最终落到
  `state.sessionAliases[sessionId]` 或
  `state.projectAliases[groupKey]`，并通过 `saveState` **原子写**
  `state.json`（tmp → rename，见 `src/state/store.ts` L53-61）。
- `d` 路由：`src/tui/keyActionRouter.ts` L128-136
  → `OPEN_MODAL` 模态 `confirm` + `confirmAction:
  'deleteManualProject'` + `confirmPayload: state.selectedProjectKey`。
  confirm 模态确认后由 `useKeybindings.onDelete` 调用
  `deleteManualProject(groupKey)`。
- `d` 写盘：`src/actions/deleteManualProject.ts` L38-46
  → 读 state → `manualProjects.filter(m => path.resolve(m.path) !== groupKey)`
  → `saveState`（同样原子写）。**不会**误删自动发现的项目（filter 只在
  manualProjects 上跑）。
- `c` 路由：`src/tui/keyActionRouter.ts` L139-140
  → 当 `state.selectedSessionId` 是字符串时调用
  `opts.onCopySession(state.selectedSessionId)`。
- `c` 副作用：`src/tui/App.tsx` L215-219
  → `copySessionId(id)` → `src/actions/copySessionId.ts` L43-46
  → `execFile('pbcopy', [], { input: sessionId })`（execFile-only policy）。
- 状态文件位置：`src/state/store.ts` L6-11
  → `~/.config/cc-manager/state.json`（`XDG_CONFIG_HOME` 可覆盖）。

预期状态文件结构（重启前）：

```json
{
  "sessionAliases": { "<sessionId>": "New alias" },
  "projectAliases": { "<groupKey>": "New project alias" },
  "manualProjects": [ /* d 后数量 -1 */ ]
}
```

## 风险信号

- **中**：本任务同时需要 GUI 操作（rename / confirm 模态）与跨进程
  state 校验，沙箱无法完整复现。单元测试覆盖了 action 单步、setAlias
  持久化 round-trip、损坏文件回退——但**用户手动 rename → 模态确认 →
  state.json 落盘**这一条 UI 链路只有手动清单把关。
- **低**：原子写（tmp → rename）+ cache 失效（`saveState` 末尾
  `cache = state`）已通过 `tests/state/store.test.ts` 验证；`rename
  -a-class` 风格的多 tab 共享状态不会被 cache 失同步坑到。
- **低**：损坏 state.json 容错（备份 + defaults）已单测覆盖；本清单
  Step 11 是真实文件系统上的端到端确认。
- **已知 limitation**：`saveState` 走 tmp → rename，**最后写者覆盖**
  语义，没有文件锁——若用户在 ccsm 运行中手工改 state.json，
  下次 ccsm 写盘会覆盖手工改动。这是已知 trade-off，文档见
  `openspec/changes/cc-session-manager/design.md` Group 2。
