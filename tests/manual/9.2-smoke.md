# Task 9.2 — 真实目录冒烟测试清单

> 手动验证清单：在**真实 macOS Terminal**（真实 TTY）针对用户自己的
> `~/.claude/projects/` 启动 `ccsm`，确认项目 / session 正确出现。
>
> 本清单需要交互式 TTY，无法在沙箱 / CI 中自动执行。请在本地终端逐步执行并勾选。

## 前置条件

- macOS，Node.js >= 18
- 已 `npm install`
- 存在 `~/.claude/projects/`，且至少有一个项目目录（本机当前有 23 个）

## 步骤

- [ ] **Step 1：构建**

  ```bash
  npm run build
  ```

  期望：命令成功，`dist/cli.js` 存在且带可执行 shebang（`#!/usr/bin/env node`）。

- [ ] **Step 2：启动（真实终端）**

  ```bash
  node dist/cli.js
  # 或 ./dist/cli.js
  # 或全局链接后 ccsm
  ```

  期望：
  - UI 正常渲染（无 "Invalid hook call" / "more than one copy of React" 报错）。
  - 左栏出现 **Projects (N)** 列表，N 与 `ls ~/.claude/projects | wc -l` 大致对应（会跳过空 / 无 session 的目录）。
  - 选中某项目后，右栏出现该项目的 **Sessions (N)** 列表，含标题 / 相对时间。

- [ ] **Step 3：基本导航冒烟**

  - [ ] 上下键在项目列表移动，右栏 session 随之刷新。
  - [ ] Tab / 焦点切换在 Projects ↔ Sessions 间工作。
  - [ ] `/` 或搜索键唤起 session 搜索，输入关键词能过滤。
  - [ ] `q` 或 Esc 能正常退出，终端回到正常状态（无残留 raw mode、光标可见）。

- [ ] **Step 4：真实数据正确性抽查**

  - [ ] 任取一个项目，核对右栏 session 数量与 `ls ~/.claude/projects/<encoded-dir>/*.jsonl | wc -l` 一致。
  - [ ] session 标题 / 最近活跃时间显示合理（非 `Invalid Date`、非空）。

- [ ] **Step 5：人工记录结果**

  在个人笔记 / README 草稿记录截图或行为观察。**此步不进入仓库。**

- [ ] **Step 6：如发现问题**

  归类后提交修复：

  ```bash
  git commit -m "fix(integration): <description>"
  ```

## 沙箱可自动确认的部分（已执行）

即便没有 TTY，也可确认打包产物能加载 React 而不崩溃：

```bash
node dist/cli.js </dev/null; echo "exit=$?"
```

期望：无 React "Invalid hook call" 报错，`exit=0`。
（在非 TTY 下 Ink 不会真正渲染交互界面，只验证"启动不崩溃"。）

## 已知历史问题（本任务已修复）

- **duplicate React → "Invalid hook call"**：早期 `tsup.config.ts` 未把 `react`
  标为 external，React 被打进 `dist/cli.js`，而 ink（external）又从
  `node_modules` 加载另一份 React，两份实例导致 hook dispatcher 为 null、启动即崩溃。
  修复：`external: ['react']` + 将 `react` 声明为 `dependencies`。若回归，本清单
  Step 2 会立即复现。
